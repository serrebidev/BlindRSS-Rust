Audit date: 2026-11-03. Python baseline: `2a7eeb3`, v2.5.8, at
`C:/Users/admin/git/BlindRSS`. Rust baseline: `1df3af2`, v0.1.53, in this

that either checkout matches a newer remote branch or release.

This is the current outstanding-work register. It supersedes earlier open/closed

## Method and coverage

Eight parallel source reviews compared configuration and shortcuts; main-window
flows and dialogs; playback and downloads; providers, storage and refresh;
article readers; discovery and podcast archives; browser and platform integration;
and casting, maintenance and translation. Reviews traced application callers as
well as helpers, and reconciled previous audits with current implementation.
The recent Python v2.5.6–v2.5.8 fixes received an explicit comparison.

Mechanical inventory of the Python audit surface: 72 `core/*.py` files
(46,288 lines), 16 `gui/*.py` files (38,555 lines), and nine
`providers/*.py` files (12,663 lines). The Rust surface comprises 13
`app/src/**/*.rs` files (18,730 lines) and 67 `crates/core/src/**/*.rs`
files (38,654 lines). Python has 298 `test_*.py` files under `tests/`;
Rust has 59 integration-test `.rs` files under `crates/core/tests/`, in addition
to inline unit tests. File counts describe coverage boundaries, not proof that
every line or possible input was exhaustively verified.

Evidence notation: `Python path:line` is relative to the Python checkout;
`Rust path:line` is relative to this checkout. References are pinned to the
baselines above and will move as implementations change. Findings are confirmed
source differences, not reproduced live failures unless explicitly stated.

Priority: **P1** affects data, privacy, core behavior, or a major unreachable
feature; **P2** is a meaningful missing capability; **P3** is a smaller interface
or configuration difference. Priority describes implementation order, not a claim
that an exploit or incident occurred.

## Outstanding findings

  (`crates/core/src/config.rs:71`), producing nested objects which

  writes, flushes and replaces a sibling temporary file. Rust
  `crates/core/src/config.rs:90` writes directly over the shared live file.

- **S03 — P2: Per-feed columns are not applied or editable.** Python

### Providers, storage and refresh

- **D01 — P1: Stored category paths differ from Python.** Python
  `core/db.py:2536` uses `" / "`. Rust `crates/core/src/db.rs:1221,1305,1567`

  repeats it. Existing Python children can be missed or duplicated. Use one
  compatible separator and test parent membership, rename/move/delete against
  a copied Python-shaped database with repeated child leaf names.
- **D02 — P1: Category mutations leave dangling references.** Python
  `providers/local.py:5935,5978` and `core/db.py:1985` rewrite overrides,
  labels, filter/delete targets and hierarchy. Rust `crates/core/src/db.rs:1210`
  changes categories/feeds only; moving via the dialog does not change
  `parent_id`. Make mutations transactional and preserve every reference,
  including global/per-feed configuration targets and nested descendants.
- **D03 — P1: Local IDs collide across feeds.** Python
  `providers/local.py:3965,4359` scopes conflicting IDs. Rust
  `crates/core/src/refresh.rs:18,60` inserts raw IDs; `db.rs:2144` ignores the
  second feed's row but can append its history to the winner. The YouTube-only
  helper at `refresh.rs:210` is insufficient. Test GUID `1` in two feeds with
  independent state, versions, media and deletion.
- **D04 — P1: Retention and deletion permit resurrection.** Python
  `providers/local.py:4311` refuses new entries outside retention. Rust
  `crates/core/src/refresh.rs:52` and `db.rs:2144` have no insert boundary,
  while `db.rs:1719` deletes old tombstones. Enforce one retention boundary
  across relevant ingestion paths and preserve deletion identity; prune then
  refresh unchanged old entries without creating unread rows.
- **D05 — P2: Cleanup policy differs for unread/undated rows and playback.**
  Python `core/db.py:833,851` removes old unread nonfavorites, protects undated
  sentinels and cleans playback state. Rust `crates/core/src/db.rs:1710`
  requires read state, lacks the sentinel rule and leaves playback rows.
  Test old read/unread/favorite/undated combinations and dependent state.
- **D06 — P1: Existing feed metadata is never refreshed.** Python
  `providers/local.py:4257` updates date, description, URL, enclosure/type and
  chapter URL. Rust `crates/core/src/db.rs:2144` only inserts/ignores and records
  history. Synchronize publisher-owned metadata while preserving local
  read/favorite/full-text state; test a later enclosure and corrected URL.
- **D07 — P1: Inoreader token refresh is unreachable.** Python
  `providers/inoreader.py:300` refreshes expired credentials. Rust
  `crates/core/src/provider.rs:191` reads a static access token; the helper at

  rotating refresh tokens, revoked grants and transient failures without
  discarding the working account cache.
- **D08 — P2: Inoreader AppId/AppKey headers are missing.** Python
  `providers/inoreader.py:130` sends them. Rust
  `crates/core/src/providers.rs:320` supplies only Authorization and carries no

- **D09 — P1: Hosted sync leaves remotely removed feeds cached.** Python
