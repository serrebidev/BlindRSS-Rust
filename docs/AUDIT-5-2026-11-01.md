# BlindRSS Python → Rust: Feature Audit 5 (2026-11-01)

Purpose: verify, against the CURRENT Python tree (v2.5.5) and the
CURRENT Rust tree (v0.1.36), that the port plan (docs/PARITY.md in
serrebidev/BlindRSS-Rust) misses nothing, so the remaining work can
continue in Codex with a complete list.

Method: fresh mechanical inventory (Python core/gui/providers
modules vs Rust core/app modules; 197 Python config-manager keys
diffed against Rust literals — 81 not literal, each hand-triaged),
Python git history since Audit 4 (2026-10-31) reviewed commit by
commit, PARITY.md resolution chain re-read, README feature list
cross-checked. Everything below marked CONFIRMED was verified in
both trees on 2026-11-01.

## A. Confirmed misses — in neither the plan nor the Rust tree

1. **FeedSearchDialog term search (25 sources).** Python's
   subscribe dialog (gui/dialogs.py, `_search_*` ×25) searches by
   name/term: iTunes/Apple Podcasts, gPodder, Fyyd, Podverse,
   Feedspot, Google News, Bing News, Feedly, awesome lists, news
   APIs, YouTube channels, SoundCloud, Mixcloud, Mastodon,
   Bluesky, PieFed, Groups.io, Lemmy (×2), NewsBlur, Reddit,
   Fediverse, Feedsearch, and the BlindRSS directory. Rust's
   dialog (app/src/dialogs.rs `show_feed_search`) only resolves a
   URL (subscribe transform + HTML alternate-link discovery) —
   none of the 25 term searches exist. PARITY's stale §2 row 76
   names four of them (Feedsearch/Podcast Index/Apple/Fyyd) as
   missing; no resolution paragraph ever closed it, and the row
   understates the scope. This is the largest single miss.

2. **MSAA Direct Annotation control names (Python PR #131,
   shipped in Python v2.5.5).** wx SetName never reaches MSAA, so
   Python annotates HWNDs via IAccPropServices: feed tree, search
   box, article list, reader, playback speed box get real names;
   position slider, time field, chapter list stop borrowing a
   neighbouring label; the -10 s/+10 s/Chapters buttons announce
   "Rewind 10 seconds" / "Fast Forward 10 seconds" /
   "Chapters Menu". Rust has no IAccPropServices anywhere;
   app/src/main.rs has zero set_name calls. NVDA-facing; the
   highest-value small item here. Python guard:
   tests/test_msaa_names.py.

3. **Managed yt-dlp preference (Python PR #130, v2.5.5).**
   Python's `_find_executable_path` prefers the app-managed
   yt-dlp (the copy the dependency check keeps on the nightly
   channel, `<data>/bin`) over PATH for every lookup. Rust
   `media::find_ytdlp` order is user path → BLINDRSS_YTDLP env →
   PATH; the managed copy (`dependency::managed_ytdlp`) is never
   consulted, so a stale PATH yt-dlp wins — the exact bug #130
   fixed. One fix site; all yt-dlp callers ride find_ytdlp.
   Minor companion: Python scans Windows tool paths once per
   session (96e1f2d); Rust rescans per call.

4. **Empty-extraction memory + escaped-markup unescape
   (Python PRs #133/#134, v2.5.5).** (a) Pages that download but
   yield no readable text are remembered in an LRU(256) keyed
   (url, encoding) for 15 minutes; revisits inside the TTL raise
   the same extraction error without re-downloading. Not in
   Rust extract.rs. (b) When embedded content carries ≥3
   entity-escaped block closers (`&lt;/p&gt;`, `&lt;/h2&gt;`…)
   and no real first tag, Python unescapes once before tag
   handling, else screen readers read literal "<h2>"/"<p>"
   aloud (a Nuxt-site pattern). Rust has the JSON-LD-body
   unescape but not this cascade branch.

5. **YouTube subtitle `language_match` simplification
   (Python PR #132, v2.5.5) — partial.** The Batch 35b port has
   Python's five-step ranking and the tlang machine-translation
   rules, but `language_match` lacks: the `-orig` suffix strip
   and `_`→`-` normalization on the track code, the Chinese
   script table (zh-tw/hk/mo → zh-hant, zh-cn/sg → zh-hans,
   rank 1), and Python's 0/1/2/3 rank scale (same tag / same
   script / bare base / other variant). Effect: wrong track
   preference for Chinese-script locales and `-orig` codes.

6. **Miniflux targeted refresh subsystem.** Python
   providers/miniflux.py refreshes per feed through the
   targeted-refresh machinery (~110 references): per-feed
   refresh calls, a worker pool
   (`miniflux_targeted_refresh_workers`), a 5xx limit and
   cooldown (`miniflux_targeted_refresh_5xx_limit`,
   `miniflux_targeted_refresh_cooldown_s`), a soft deadline
   (`miniflux_refresh_soft_deadline_s`), a per-feed timeout
   (`miniflux_per_feed_refresh_timeout_s`), and force-skip
   after repeated errors (`miniflux_force_skip_error_count`).
   Rust HostedProvider::refresh is one whole-account
   `sync(&db, 100)`; the Provider trait has no per-feed
   refresh for hosted providers.

7. **Main-window full-text view cache.** Python's mainframe
   caches article full text per view, capped by
   `max_cached_views` (default 15, a Settings spin control),
   with `cache_full_text` (Settings checkbox, default off)
   fetching in the background. Rust's main window has no such
   cache. (Distinct from the Accessible Browser's own
   300-entry LRU — that is Batch 37.)

8. **Article structure options.** Python Settings exposes
   `article_structure_headings/links/lists/quotes/tables`
   (defaults: tables on, the rest off); utils'
   article-structure options shape the HTML→text linearization
   the reader speaks (heading markers, inline link targets as
   "text (URL)", list/quote markers, table linearization).
   Rust has neither the settings nor the gating — its reader
   linearization is unconditional.

9. **Source listing caps are config keys in Python; Rust
   hard-codes the defaults.** `odysee_max_items_initial` (150),
   `odysee_max_items_refresh` (60), `rumble_max_pages_initial`
   (3), `rumble_max_pages_refresh` (1),
   `google_groups_max_items` (30),
   `groups_io_search_max_items` (100),
   `youtube_search_max_items` (30),
   `audio_listing_max_items_initial/refresh`. Batch 35 used
   the default values as constants; a user who tunes the keys
   in config.json (dual-run with Python) is ignored by Rust.

10. **Conditional API keys.** (a) `github_token`: Python sends
    it (env BLINDRSS_GITHUB_TOKEN / GITHUB_TOKEN / GH_TOKEN,
    then config) on GitHub REST calls in github_source.py;
    Rust threads.rs calls api.github.com unauthenticated
    (60/hr rate limit vs 5,000). (b) `groups_io_api_key`:
    Python fetches Groups.io topic bodies through the API
    when a key is configured (`_api_topic`); Batch 35 ported
    the scrape path only.

11. **Per-channel HTTP headers for playback and casting
    (core/http_headers.py).** Python builds per-channel header
    sets from feed metadata and applies them for players and
    casters. Rust has no playback header plumbing at all (the
    Batch 36 gate accepts headers but the player passes none).
    Decide with Batch 38, which re-plumbs the player anyway.

12. **Article-window rich-view navigation policy
    (gui/rich_view_links.py).** The main window's rich reader
    intercepts navigation (external open, main-frame only,
    user-initiated); the Batch 35b article window's WebView has
    no handler, so a clicked link navigates the small window
    away from the article.

13. **Installed-browser cookie import consent gate.** Python
    gates importing cookies from installed browsers behind
    `installed_browser_cookie_import_enabled` (default False,
    explicit consent; core/site_cookies.py). Rust's cookie
    import paths key off `auto_import_browser_cookies`.
    Codex should confirm the manual Chromium import honours an
    equivalent consent before it runs.

14. **Installed-browser true-version UA detection.** Python's
    "auto" fetch identity claims the actually-installed
    browser at its real version; Rust user_agents.rs resolves
    auto to the platform preset and records the detection as
    not ported (module doc). Stale fetch identity is a bot
    signal on the sites this feature exists for.

## C. Warnings for whoever continues

- **PARITY.md's early tables contradict its resolutions.**
  The §1/§2 status tables and §5 lists are pre-batch
  snapshots; roughly fifteen rows still say "missing" or
  "partial" for shipped work (HTML rendering, source feeds,
  forum sources, EQ, single instance, updater, YouTube
  account…). The Batch 22+ resolution paragraphs and this
  audit govern. A reconciliation pass over the tables would
  prevent re-porting shipped features.
- Python test suite is 2,508 tests; Rust's is 244. Parity so
  far is behavioural with targeted regression slices per
  batch, not test-count parity.
- Two Python config keys in the raw diff are state, not
  settings (`downloaded_media`, `site_cookies_full_*`) —
  no action.
- Cleared false positives (do not re-chase): translation
  provider keys (Rust builds `translation_<provider>_*`
  dynamically, like Python); menu mnemonics (Rust menus use
  & markers); updater check + verified stage (core/
  maintenance.rs; only the final apply step deserves a
  once-over); JSON-LD entity unescape (present); YouTube
  subtitle ranking framework (present — only item 5's
  matcher is simplified); social subscribe transforms and
  forum thread reconstruction (present); media-key support
  is Python's in-app command model (keys.rs covers the
  commands; hold-to-repeat seek behaviour is worth one
  check against mainframe.py's custom repeat handling).
