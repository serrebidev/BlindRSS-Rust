# Audit 6 — complete audit: Python BlindRSS v2.5.5 vs BlindRSS-Rust v0.1.39

Date: 2026-11-01 (owner's order: "Complete auditing the app
completely", plus the GUI parity directive: the Rust GUI must
look exactly like Python BlindRSS). Method: mechanical
inventories and diffs of both trees (menus, commands, dialogs,
providers, locales, help topics), targeted source reads, and
the PARITY resolutions + Audit 5 + the Codex gap list as the
baseline. Raw extraction files: reports/audit6/.

## Verdict

The functional core is at parity: the shortcut command
registry is identical (70 of 70 commands, no diff), all 15
locales match, help topics are a superset of Python's 27,
every Python provider and source reader is present, and
every Python dialog has a Rust counterpart except the items
below. The remaining distance is concentrated in ONE area:
the GUI's exact shape. The Rust app implements the same
features behind menus, context menus, a settings dialog and
a tray menu that are arranged differently from Python's.
Under the owner's look-exactly directive those differences
are now defects, and they form one GUI parity batch (G1).
Two functional gaps ride along (G2, G3). One owner-directed
deviation (D1) is recorded so it is never re-litigated.

## G1 — GUI parity diffs (all verified against source)

1. Menu bar. Python's bar is File / Feeds / Edit / View /
   Player / Tools / Help with this exact assignment:
   File = Open Article..., Open Media URL..., Mark All Items
   as Read, Add Category, Remove Category, Back Up Data...,
   Restore Data..., Configure Persistent Search..., Add
   Shortcuts... (Windows only), Exit. Feeds = Add Feed,
   Detect Feeds on Page..., Remove Feed, Refresh Feeds, Stop
   Refresh, View Feed Errors..., Import OPML..., Import
   YouTube Takeout..., Export OPML.... View = Show Search
   Field, Rich Full-Text View, Article Filter submenu, Open
   Accessible Browser (see D1), Show/Hide Player, Sort By
   submenu. Player = Show/Hide Player, Play/Pause, Stop,
   Play Queue..., Play Next/Previous in Queue, Equalizer...,
   a Playback Speed submenu, a Chapters submenu, Rewind /
   Fast Forward / Volume Up / Volume Down with their
   shortcut text. Tools = Find a Podcast or RSS Feed...,
   Podcast Archive..., Video Search..., Filter Rules...,
   Import Site Cookies..., YouTube Account..., Keyboard
   Shortcuts..., Settings.... Help = User Guide, Check for
   Updates..., Announce Version, About.
   The Rust bar reassigns many of these (feed operations in
   a Feeds menu shaped differently, Backup.../Restore...
   wording instead of Back Up Data.../Restore Data..., no
   Open Article/Open Media URL in File, no Article Filter or
   Sort By submenus in View, no speed/chapters submenus in
   Player, several article operations promoted into the bar
   that Python keeps in context menus only). Rebuild the bar
   to Python's map, item for item, label for label, mnemonic
   for mnemonic (gui/menu_mnemonics.py is the authority).
2. Context menus. Python's tree context menu varies by node
   kind (category: Refresh Category, Mark All Items as Read,
   Add Subcategory, Edit Category, Remove Category, Delete
   Category and Feeds, Import OPML Here..., Export Category
   to OPML...; feed: Refresh Feed, Mark All Items as Read,
   Edit Feed..., Reset Title to Feed Default, Copy Feed URL,
   Remove Feed; smart folder: New/Edit/Delete Smart Folder;
   plus an Image Alt Text submenu). The article list context
   menu is selection-aware (Mark {count} as Read/Unread,
   Add {count} to Play Queue, Remove {count} from Play
   Queue) and carries Open Article, Open in Default Browser,
   Copy Links, View Feed Description..., Copy Media Link,
   Download, Download As..., Detect Audio, Copy Image Link,
   Open Play Queue..., View History..., and a Chapter Links
   submenu. The reader content context menu is Copy / Select
   All only. The Rust context menus cover most actions but
   not with these labels, groupings, or the count-aware
   variants. Align all three.
3. Settings dialog. Python is a Notebook with pages in this
   fixed order: General, Feeds & Articles, YouTube,
   Media Player, Provider, Notifications, Translate,
   List Headers, Advanced, CAPTCHA Solving, plus a Downloads
   panel shown contextually. Python's own comment states the
   rule: never insert a page mid-notebook, tab positions are
   screen-reader muscle memory. The Rust settings dialog is
   one long single page of headings. Restructure into the
   same notebook, same page order, same control order inside
   each page (the per-row audit rides with the restructure).
4. Tray menu. Python: Unread: {count} label, Restore,
   Show/Hide Player, Refresh Feeds, Play/Pause, Stop,
   Rewind, Fast Forward, Volume Up, Volume Down. Rust: Show
   BlindRSS, Refresh All, Exit only. Port Python's set.
5. Article window. Python's article window has File / Edit /
   View menus; the Rust one has a different menu shape
   (Article menu). Align.
6. Category Properties. Python's dialog offers rename plus
   a parent-category picker ("(None - Top Level)"). Rust
   renames via a path field (functionally equivalent —
   categories are paths) but has no picker dialog. Match
   the dialog shape.
7. Main window + player panel surfaces. Status bar fields
   and widths, the toolbar button row, player panel control
   order and the chapter list presentation get a line-by-line
   sweep inside the same batch against mainframe.py and
   player.py (the extraction anchors are in
   reports/gui-parity-plan.md).

## G2 — Add Shortcuts dialog (Windows) missing

Python ships AddShortcutsDialog + the File menu's
"Add Shortcuts..." item (Windows only): create Desktop,
Start Menu and taskbar shortcuts. No Rust counterpart
(startup.rs covers start-at-login only). Small Windows-only
batch: create the .lnk files via the same shell-link path
the Python app uses.

## G3 — Feed-search source count (already tracked, restated)

Python's FeedSearchDialog searches 25 named sources; the
Rust port covers 7 plus combined search (Audit 5 §3). This
stays on the source-depth backlog with gaps 3–4; the audit
confirms no additional sources were missed beyond the 18
already counted.

## D1 — Owner-directed deviation: Accessible Browser dropped

At the owner's direction (2026-11-01) the Accessible Browser
is removed from the Rust port: research across GitHub
(most-recent and most-starred), Codeberg and GitLab (both
empty) found no Rust/wx project that requires a separate
macOS GUI for VoiceOver; blind-focused wxDragon apps
(BrailleCraft, Wixen Mail) ship one GUI for all platforms;
wxDragon upstream maintains VoiceOver support in the main
surface; wxWidgets 3.3.x improved wxOSX accessibility and
closed the historic wxListCtrl/VoiceOver tracker item as
completed. Python keeps its Accessible Browser (it is the
primary VoiceOver reading surface there); the deviation is
Rust-only and deliberate. Consequences: the Rust shortcut
registry intentionally diverges from Python's by one command
(view.accessible_browser), the View menu loses that item,
and the core accessible module + Db::articles_page leave
with it. Recorded in PARITY as the Batch 40 resolution.
