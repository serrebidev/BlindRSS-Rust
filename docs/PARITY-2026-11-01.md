# Feature parity audit and ports: 2026-11-01

Historical report. Current outstanding status is maintained in
[Audit 8, 2026-11-03](AUDIT-8-2026-11-03.md) and its
[implementation plan](superpowers/plans/2026-11-03-parity.md).
Several gaps below were subsequently implemented, while fresh caller-level
review found other incomplete behaviors; do not reuse this list as today's queue.

Reference application: `C:/Users/admin/git/BlindRSS`, Python version 2.5.5,
commit `1b44e07209bc7aa72db2f75a64f5d0056e62902d`.
Rust baseline: version 0.1.34, commit `9ceecdb`.

This comparison covers the two applications' feed/data paths, providers,
discovery, extraction, downloads, playback, menus, shortcut registries, settings,
and help. The expected workload is one desktop user with background feed and
media workers. The older `PARITY.md` contains historical entries that still say
“missing” for features implemented in later batches. This audit checked the
current source instead of treating those labels as evidence.

**Full feature parity has not been established.** The ports below are implemented;
the remaining gaps below are still work. This is a feature comparison, not a
separate accessibility certification or an exhaustive security audit.

## Implemented

### Feed parsing, storage, and filters

- Select article links rather than mistakenly using Atom self/enclosure links.
- Preserve feed categories/tags when parsing and storing entries.
- Read Python newline-separated tags and older Rust JSON tags. Merge enrichment
  without losing existing Python tags; write the Python-compatible format.
- Evaluate existing-article filters with actual tags, opened state, and updated
  state. Skip unknown rule fields instead of letting an unknown OR branch match
  everything.
- Import the owner's channel from YouTube Takeout `channel.csv`; handle BOM and
  non-ASCII history links. Reject archives with more than 20,000 members and
  members larger than 64 MiB.
- Use persisted ETag/Last-Modified validators for cached refresh. Keep the
  validated response body so an unsuccessful article-store operation can retry
  after a later 304 response. Manual refresh bypasses validators; automatic
  refresh honors cached/startup-full/always-full policy.
- Apply imported site cookies and browser client hints to feed requests. Preserve
  the existing one-time certificate-error fallback.

Implementation: `feeds.rs`, `refresh.rs`, `db.rs`, `rules.rs`, `takeout.rs`.

### Hosted readers

- Page through Miniflux entries, including read history. Import bookmarks and
  refresh existing article content, read state, favorites, and feed metadata.
- Follow Google Reader continuation tokens and import server read/starred state.
- Perform remote read/favorite writes before updating the cache in the provider
  interface. Set Miniflux bookmarks to the requested state instead of blindly
  toggling them.
- Send Miniflux OPML imports as XML, matching the reference application's API use.
- Scope Inoreader in-memory caches to the account and endpoint. An account change
  no longer reuses another account's subscription/article cache.
- Add tested Miniflux client operations for category creation and feed editing.
  These client operations are **not yet wired into every GUI mutation path**.

Implementation: `providers.rs`, `provider.rs`, `db.rs`.

### Discovery and article reading

- Search Apple Podcasts, gPodder, fyyd, Podverse, Feedly, NewsBlur, and Feedsearch
  by text. Integrate named providers and combined search into Find Feeds.
- Discover every advertised feed from a URL and probe common feed locations.
  Improve relative URL resolution and reject misleading social-host matches.
- Support additional YouTube user/playlist URL shapes.
- Subscribe to Google Groups and Groups.io archive-search pages as synthetic
  feeds. Refresh them through the normal feed path; use imported cookies and
  bounded same-source pagination. Add native Groups.io and Google Developer
  Forums RSS transformations.
- Follow up to six article pages in both readers. Reject cross-origin or
  protocol-changing next links, detect loops, and avoid duplicate page bodies.
- Preserve configurable table descriptions, heading levels, list markers,
  quotations, and inline link targets. Enter opens a link on the current reader
  line when inline links are enabled.
- Show the metered-preview notice in rich view, clearing it when complete feed
  content replaces the preview.
- Give standalone article windows plain/rich switching, reload, source-browser,
  copy-text, copy-link, and close commands. Ignore stale asynchronous results.
- Fix source-checkout help lookup to use this repository's bundled guide.

Implementation: `discovery.rs`, `feedsearch.rs`, `forum_sources.rs`, `extract.rs`,
`article_html.rs`, `app/src/article_window.rs`, `dialogs.rs`, `help.rs`.

### Downloads and podcast history

- Record the actual completed yt-dlp output file, not its containing directory.
- Read and write Python's hashed `downloaded_media` index, including older
  string entries. Prefer available local files for activation, playback, and
  queue advancement. Fall back when indexed files have been removed.
- Add Download As and batch download actions.
- Preserve existing files when a direct download fails. Publish completed
  downloads without replacing another writer's file; support destinations
  without hard links.
- Choose YouTube subtitles by interface language, English, and original-language
  preference. Parse JSON3 captions and comments/replies without shared temporary
  subtitle files.
- Recover podcast history from multiple Wayback snapshots and migrated feed
  URLs, rather than only the newest snapshot. Continue when the live feed is
  unavailable. Bound document size, lineage, and snapshot count; preserve the
  first encountered episode metadata when identifiers overlap.

Implementation: `download.rs`, `media.rs`, `archive.rs`, app download/play callers.

## Remaining confirmed gaps

1. **Hosted account storage isolation.** Hosted feed/article rows still share the
   main database namespace. GReader services use colliding `feed/<URL>` IDs.
   Scoping the in-memory cache fixes one leak, not the persistent namespace.
   Account-specific storage/migration and provider-view filtering are outstanding.
2. **Complete hosted mutation behavior.** GUI feed properties, category creation,
   and category reassignment do not all use the remote client operations. Some
   GUI read/favorite paths still update locally before asynchronous remote
   propagation. Failure handling and provider-wide mark-all-read need a further
   end-to-end pass.
3. **Specialized source readers.** Python's complete GitHub PR reviews/diffs,
   commits, releases, and discussions are deeper than `threads.rs`. Invision,
   vBulletin, XenForo, Google Groups conversation rebuilding, and other HTML
   thread readers remain incomplete. Creating a Groups feed is not equivalent
   to reconstructing each entire conversation.
4. **Specialized subscriptions and searches.** SoundCloud/Mixcloud synthetic
   listing feeds, Rumble/Odysee/NPR/Sky source depth, some social/directory
   searches, and YouTube RSS-error/uploads-backfill paths remain incomplete.
5. **Browser-backed retrieval.** Python's browser feed detector, warm-browser
   challenge handling, TLS impersonation, and Windows v20 app-bound cookie
   extraction are not ported completely.
6. **Podcast archive state.** Automatic scan scheduling, progress/cancellation,
   hosted account-scoped sidecar state, richer episode identity reconciliation,
   retries, and the complete archive manager are still shallower than Python.
7. **General playback range cache.** The existing LAN stream/transcode proxy is
   not Python's general disk-backed byte-range cache. Cancellation, incremental
   silence analysis, WebRTC VAD, and fast InnerTube chapter retrieval also remain.
8. **Casting depth.** The new persistent controls cover Chromecast. Equivalent
   sessions, seek/resume, and queue behavior across AirPlay/DLNA/Sonos/Roku/Kodi
   are not complete. No physical device was exercised during this work.
9. **Reader special cases.** Rich YouTube reconstruction, ID3 show notes,
   Google News-specific proxy behavior, and publisher-specific rich HTML
   expansions remain incomplete. Plain-text and HTML extraction still have
   differences outside the tested fixtures.
10. **Interface breadth.** Menu-highlight F1, complete translation coverage,
    specialized browser/account shortcuts, and exact Python dialog behavior
    remain incomplete. Not every registered command represents a ported feature.
11. **Platform acceptance.** Linux VLC video embedding is not implemented in
    the new backend; macOS/Linux GUI behavior and packaging were not tested here.
    Installed VLC 3 is used when available; bundling/installing it in release
    artifacts still needs validation.

## Verification and limits

- Workspace builds and all-target Clippy run on Windows; warnings are errors.
- Workspace regression suite: 371 passed, 2 ignored (the libVLC smoke and the
  installed-Chromium browser check, both gated on installed runtimes).
- Installed libVLC 3 smoke: silent WAV playback, seeking, rate changes, equalizer,
  soundcard enumeration, and shutdown passed.
- Tests use temporary databases, local HTTP fixtures, and supplied article
  fixtures. They do not access the user's hosted accounts or personal database.
- NVDA/Braille, live provider behavior, physical casting devices, macOS/Linux
  builds, and release packaging were not validated. Independent agent review
  could not finish after the workers reached their usage limit; integration
  review continued in the main session.
- The repair loop left open by that interruption was finished on 2026-11-02 and
  the gate re-run end to end: `cargo fmt`, all-target Clippy at zero warnings,
  `cargo test --workspace` (371 passed, 0 failed), and `cargo build -p
  blindrss` all pass.
- No release, version bump, commit, push, or Python-checkout modification was
  performed. The untracked `agents.md` instructions file was left untouched.
